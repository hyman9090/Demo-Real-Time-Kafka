Consumer groups 有各自獨立的 offsets；一組失敗不會回滾另一組已完成的處理。

orders-audit-2 · 暫時性 DB 錯誤

PostgreSQL 錯誤重試 3 次；仍失敗就停止 consumer。audit-1 不受影響，audit-2 訊息會留待同一 group 稍後重試。

不提交 audit-2 offset · 不送 DLQ

orders-dlq 幾時用？只用於無效訊息

Null payload、無效 JSON、UTF-8 解碼失敗或訂單 schema 驗證失敗，會由各自的 consumer group 獨立處理。

寫入共用 orders-dlq

每個 envelope 記錄來源 topic / partition / offset、原因及 consumer group；不同 group 可各自產生一筆。

consumer_group=orders-to-postgres consumer_group=orders-audit-1 consumer_group=orders-audit-2
→
確認 delivery 後提交來源 offset

DLQ delivery 失敗或 timeout：不提交來源 offset，保留稍後重試。

重要：PostgreSQL 寫入錯誤不會送 DLQ。若 DLQ delivery 已成功但來源 offset commit 失敗，重試可能留下重複 envelope（at-least-once）。

Broker 寫入保護

兩份副本且 min ISR=2。若 ISR 少於 2，寫入可能暫停或失敗，不會以單一副本確認成功。

錯誤及重試

PostgreSQL 錯誤重試 3 次；耗盡後 consumer 停止並保留來源 offset，不會把資料庫錯誤送進 DLQ。DLQ 則採 at-least-once，來源 offset commit 失敗時可能有重複封套。
